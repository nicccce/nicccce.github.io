Chapter 1: Introduction to Reinforcement Learning

1.1 What Is Reinforcement Learning?

Reinforcement Learning (RL) is a mathematical framework for learning-based decision making. Its central idea is:

  • An agent interacts with an environment.
  • The agent chooses actions.
  • The environment returns observations and rewards.
  • The agent learns from experience to choose better actions in the future.

In other words, RL studies how an agent improves behavior through trial and error. Unlike many machine learning settings, the learner is not given a fixed dataset: its actions influence the data it will see next.

1.2 The Agent-Environment Loop

A typical RL problem contains the following components:

  • Agent: the learner or decision maker.
  • Environment: the world the agent interacts with.
  • Action: a decision made by the agent.
  • Observation / State: information the agent receives from the environment.
  • Reward: a scalar feedback signal that tells the agent how good or bad the outcome was.

The interaction loop is:

  1. The agent observes the current situation.
  2. The agent selects an action.
  3. The environment changes as a consequence of the action.
  4. The agent receives a new observation and a reward.
  5. The agent updates its behavior.

The goal is to learn a policy that chooses actions to maximize long-term reward.

1.3 How RL Differs from Supervised Learning

In supervised learning, the training data usually consists of input-output pairs:

The learner is told what the correct answer should be.

In reinforcement learning, the situation is different:

The agent is not directly told the correct action. It only receives feedback through rewards.

Important differences include:

  • Data is not i.i.d. Previous actions affect future observations.

  • There is no fixed ground truth label. The agent may only know whether an outcome was good or bad.

  • Actions change the data distribution. The agent's own behavior determines what experience it collects.

  • The goal is long-term performance. A locally good action may lead to poor future outcomes, while a costly action now may produce larger rewards later.

This makes RL a decision-making problem rather than just a prediction problem.

1.4 Examples of RL Problems

RL applies whenever an agent must make repeated decisions from feedback.

Robotics

For a robot:

  • Actions may be motor torques or currents.
  • Observations may be camera images, joint angles, or sensor readings.
  • Rewards may measure task success, speed, stability, or energy efficiency.

Examples include locomotion, navigation, manipulation, and complex physical control tasks.

Games

For a game-playing agent:

  • Actions are legal moves or controller inputs.
  • Observations are board states, pixels, or game states.
  • Rewards may be win/loss signals or game scores.

AlphaGo's famous "Move 37" is an example of RL discovering a strategy that surprised human experts.

Business and Operations

For inventory or purchasing decisions:

  • Actions are what to buy, sell, or allocate.
  • Observations are inventory levels, prices, and demand.
  • Rewards are profit or cost reduction.

Language Models

RL can also be used to improve language models through feedback. In reinforcement learning from human feedback (RLHF), a model is optimized according to preference-based reward signals rather than only next-token prediction.

Image Generation

RL can optimize generative models toward desired objectives, such as human preference, aesthetic quality, or task-specific reward functions.

Chip Design

RL has been used for chip floorplanning, where the agent learns how to place components to optimize performance, power, or area.

1.5 Why Reinforcement Learning Matters

A major reason to study RL is that it combines learning from data with optimization through search or trial and error.

Data-driven AI is good at learning patterns from examples, but imitation alone may not discover behavior better than the demonstrations. RL adds an objective and lets an agent search for goal-achieving behavior, even when humans did not explicitly demonstrate it.

This is why RL is especially interesting for tasks where:

  • The correct answer is not known in advance.
  • The agent must interact with the world.
  • Success depends on sequences of decisions.
  • New and unexpected strategies may be valuable.

1.6 Learning and Search

The lecture connects reinforcement learning to a broader view of intelligence: learning extracts patterns from data, search uses computation to find decisions, and optimization improves decisions according to an objective.

Deep reinforcement learning combines two of these ingredients: deep learning supplies scalable function approximation, while RL supplies the objective for sequential decision making.

This combination makes it possible to learn policies from high-dimensional observations such as images, language, and sensor streams.

1.7 Why Deep Reinforcement Learning?

Deep reinforcement learning is useful because real-world decision problems often involve rich and complex inputs.

Examples:

  • A robot must interpret camera images and proprioceptive signals.
  • A self-driving car must react to road scenes.
  • A language model must generate useful responses.
  • A game agent may need to act directly from pixels.

Deep networks can represent complex policies and value functions, while RL defines the objective for improving behavior.

Thus:

1.8 Key Takeaways

  • Reinforcement learning is a framework for learning how to act.
  • The agent learns by interacting with an environment and receiving rewards.
  • RL differs from supervised learning because the data depends on the agent's own actions.
  • The goal is not just prediction, but long-term decision quality.
  • RL is useful for games, robotics, operations, language models, image generation, chip design, and many other domains.
  • Deep RL combines the representation power of deep learning with the optimization perspective of reinforcement learning.
  • RL is important because it can discover new solutions rather than only imitate existing data.

Chapter 2: Supervised Learning of Behaviors

2.1 From Supervised Learning to Imitation Learning

Supervised learning estimates a conditional model from labeled examples:

\[ x \to y \]

For behavior learning, the same idea can be used to learn actions from demonstrations:

\[ \text{observation} \to \text{action} \]

This is called imitation learning. Instead of designing a reward function and solving an RL problem, we collect demonstrations from an expert and train a policy to imitate the expert's actions.

The simplest form of imitation learning is behavioral cloning.

2.2 Sequential Decision-Making Setup

In a sequential environment, the agent repeatedly receives observations and chooses actions.

A trajectory can be written as:

\[ \tau = (o_1, a_1, o_2, a_2, \ldots, o_H, a_H) \]

where:

  • o_t is the observation at time t.
  • a_t is the action at time t.
  • H is the horizon, or trajectory length.

In the partially observed case, the policy uses observations:

\[ \pi_\theta(a_t \mid o_t) \]

In the fully observed case, the observation is the state:

\[ o_t = s_t \]

\[ \pi_\theta(a_t \mid s_t) \]

The environment dynamics are usually written as:

\[ p(s_{t+1} \mid s_t, a_t) \]

This expresses the Markov property: the next state depends on the current state and action, not directly on the full past history.

2.3 Demonstration Trajectories

A demonstration trajectory is an example of expert behavior.

For imitation learning, the dataset has the form:

\[ \mathcal{D} = \left\{(o_1^{(i)}, a_1^{(i)}, \ldots, o_H^{(i)}, a_H^{(i)})\right\}_{i=1}^{N} \]

Each trajectory is produced by an expert policy, often denoted pi*.

The goal is to learn a policy pi_theta that chooses actions similar to the expert:

\[ \pi_\theta(a_t \mid o_t) \approx \pi^*(a_t \mid o_t) \]

2.4 Behavioral Cloning

Behavioral cloning treats imitation learning as ordinary supervised learning.

The algorithm is:

  1. Collect demonstrations from an expert.
  2. Create a dataset of observation-action pairs.
  3. Train a policy network by maximum likelihood.

The training objective is:

\[ \arg\max_{\theta} \sum_{i=1}^{N} \sum_{t=1}^{H} \log \pi_\theta(a_t^{(i)} \mid o_t^{(i)}) \]

Equivalently, we minimize the negative log-likelihood of the expert actions.

For discrete actions, such as game controls or language tokens, the model usually outputs logits over actions.

For continuous actions, such as steering angle or robot torque, the model often outputs distribution parameters, such as the mean and variance of a Gaussian.

2.5 Why Behavioral Cloning Is Attractive

Behavioral cloning is simple and scalable.

It can use the same tools as supervised learning:

  • neural network encoders such as ResNet or ViT,
  • cross-entropy loss for discrete actions,
  • Gaussian likelihood or regression loss for continuous actions,
  • large demonstration datasets.

It has been used successfully in systems such as autonomous driving, where the policy maps camera observations to control actions.

However, its simplicity hides an important problem: the data distribution during training is not necessarily the same as the data distribution during deployment.

2.6 Distributional Shift

In supervised learning, we usually assume that training and test examples are drawn from the same distribution.

Behavioral cloning violates this assumption.

During training, observations come from expert trajectories:

\[ o_t \sim p_{\text{data}}(o_t) \]

During deployment, observations come from the learned policy's own behavior:

\[ o_t \sim p_{\pi_\theta}(o_t) \]

If the learned policy makes a small mistake, the environment may move to states that the expert demonstrations rarely visited. The policy is then asked to act on unfamiliar inputs, which can cause more mistakes.

This feedback loop is the key reason behavioral cloning is harder than ordinary supervised learning.

2.7 Error Compounding Over Time

Consider the fully observed case for simplicity.

Define a cost for taking a wrong action:

\[ c(s_t, a_t) = \begin{cases} 0, & a_t = \pi^*(s_t) \\ 1, & \text{otherwise} \end{cases} \]

The expected cost at a state is the probability of making a mistake:

\[ \mathbb{E}_{a_t \sim \pi_\theta(a_t \mid s_t)} \left[c(s_t, a_t)\right] = \pi_\theta(a_t \ne \pi^*(s_t) \mid s_t) \]

The total expected number of mistakes over a horizon H is:

\[ \sum_{t=1}^{H} \mathbb{E}_{s_t \sim p_{\pi_\theta},\, a_t \sim \pi_\theta} \left[c(s_t, a_t)\right] \]

Suppose the learned policy has small error on the training distribution:

\[ \mathbb{E}_{s_t \sim p_{\text{train}}} \left[\pi_\theta(a_t \ne \pi^*(s_t) \mid s_t)\right] \le \epsilon \]

This does not guarantee small rollout error. After the policy makes mistakes, the state distribution can drift away from p_train.

In the worst case, the total error can scale as:

\[ O(\epsilon H^2) \]

This quadratic dependence on the horizon is much worse than the linear behavior we would hope for if each time step were independent:

\[ O(\epsilon H) \]

2.8 Why the Worst Case Can Be Pessimistic

The quadratic bound above is a worst-case analysis.

In many real systems, the environment may be forgiving:

  • small mistakes can be corrected later,
  • nearby states may require similar actions,
  • the policy may generalize beyond the exact training distribution,
  • demonstrations may contain recovery behavior.

This creates a useful paradox: imitation learning can work better when the dataset includes some mistakes and recoveries, because the learner sees how to return from off-expert states.

Still, the theory explains why behavioral cloning is fragile for long-horizon control tasks.

2.9 DAgger: Dataset Aggregation

DAgger, short for Dataset Aggregation, is designed to reduce distributional shift.

The central idea is:

The algorithm is:

  1. Train an initial policy pi_theta on expert demonstrations.
  2. Run pi_theta to collect states or observations from its own rollout distribution.
  3. Ask the expert to label those visited states with the correct actions.
  4. Aggregate the new labeled data into the dataset.
  5. Retrain the policy and repeat.

In notation:

\[ \mathcal{D} \leftarrow \mathcal{D} \cup \mathcal{D}_{\pi} \]

where D_pi contains states visited by the learned policy, labeled by the expert.

DAgger tries to make the training distribution match the deployment distribution:

\[ p_{\text{data}}(o_t) \approx p_{\pi_\theta}(o_t) \]

This directly targets the main failure mode of behavioral cloning.

2.10 Practical Ways to Improve Behavioral Cloning

Besides DAgger, several practical choices can make behavioral cloning more reliable:

  • Use larger and more diverse demonstration datasets.
  • Include recovery demonstrations from imperfect states.
  • Add data augmentation when observations are high-dimensional.
  • Use powerful models that make fewer single-step mistakes.
  • Use multi-task data so the policy learns more robust representations.
  • Combine imitation learning with reinforcement learning when reward feedback is available.

The key is to reduce the mismatch between training inputs and deployment inputs.

2.11 Key Takeaways

  • Behavioral cloning learns a policy by supervised learning on expert demonstrations.
  • The standard objective is maximum likelihood of expert actions.
  • Behavioral cloning is easy to implement but can suffer from distributional shift.
  • Small errors can compound because actions affect future observations.
  • Worst-case imitation error can grow quadratically with the horizon.
  • DAgger reduces distributional shift by collecting expert labels on states visited by the learned policy.
  • Recovery behavior and diverse data are often crucial for long-horizon tasks.

Chapter 3: Markov Decision Processes and Reinforcement Learning Basics

3.1 Markov Chain and Markov Decision Process

A Markov Chain is the most basic probabilistic model of a dynamical system. It consists of: - A state space \(\mathcal{S}\). - A transition probability function \(p(s_{t+1} \mid s_t)\) representing the probability of moving to the next state given only the current state (Markov property).

A Markov Decision Process (MDP) extends the Markov Chain by adding actions and rewards: - A state space \(\mathcal{S}\). - An action space \(\mathcal{A}\). - A transition probability function \(p(s_{t+1} \mid s_t, a_t)\) mapping a state-action pair to a distribution over the next states. - A reward function \(r(s_t, a_t)\) returning a scalar feedback signal. - A discount factor \(\gamma \in [0, 1)\).

A Partially Observed Markov Decision Process (POMDP) further generalizes this by assuming the agent does not directly observe the state \(s_t\): - An observation space \(\mathcal{O}\). - An emission probability function \(p(o_t \mid s_t)\) describing what observations are generated by the underlying state.

3.2 The RL Objective

The objective of reinforcement learning is to find a policy \(\pi_\theta(a_t \mid s_t)\) that maximizes expected return. For a finite horizon, this is often written as:

\[ \arg\max_\theta \mathbb{E}_{\tau \sim p_\theta(\tau)} \left[ \sum_{t=1}^H r(s_t, a_t) \right] \]

where a trajectory \(\tau\) is a sequence of states and actions: \(\tau = (s_1, a_1, s_2, a_2, \dots, s_H, a_H)\), and the trajectory distribution under policy \(\pi_\theta\) is:

\[ p_\theta(\tau) = p(s_1) \prod_{t=1}^H \pi_\theta(a_t \mid s_t) p(s_{t+1} \mid s_t, a_t) \]

If future rewards should count less than immediate rewards, insert a discount such as \(\gamma^{t-1}\) inside the sum. For infinite horizon (\(H \to \infty\)), the same idea is often written using the stationary or discounted state-action distribution \(d^{\pi_\theta}(s, a)\):

\[ \arg\max_\theta \mathbb{E}_{(s, a) \sim d^{\pi_\theta}} [r(s, a)] \]

3.3 Anatomy of an RL Algorithm

A reinforcement learning algorithm consists of three main components in a loop:

  1. Generate Samples: The agent interacts with the environment using its current policy \(\pi_\theta\) to collect trajectories.
  2. Estimate Return / Fit a Model: Evaluate how good the collected behaviors are. This can involve fitting a model \(p(s' \mid s, a)\), learning Q-values, or summing Monte Carlo returns.
  3. Improve Policy: Update the policy parameters \(\theta\) to make higher-reward behaviors more likely.

3.4 Value Functions and Q-Functions

Because actions matter mainly through their future consequences, RL algorithms usually estimate returns with two related functions: - Q-function \(Q^\pi(s_t, a_t)\): The expected return starting from state \(s_t\), taking action \(a_t\), and following policy \(\pi\) thereafter:

\[ Q^\pi(s_t, a_t) = \mathbb{E}_{\tau \sim \pi} \left[ \sum_{t'=t}^H r(s_{t'}, a_{t'}) \;\middle|\; s_t, a_t \right] \]

  • Value function \(V^\pi(s_t)\): The expected return starting from state \(s_t\) and following policy \(\pi\) immediately:

\[ V^\pi(s_t) = \mathbb{E}_{a_t \sim \pi} [Q^\pi(s_t, a_t)] \]

The key relation is the Bellman expectation equation, which decomposes "future return" into immediate reward plus discounted future value:

\[ Q^\pi(s_t, a_t) = r(s_t, a_t) + \gamma \mathbb{E}_{s_{t+1} \sim p} [V^\pi(s_{t+1})] \]

3.5 Taxonomy of RL Algorithms and Tradeoffs

RL algorithms differ based on their design choices and assumptions:

  1. Policy Gradients: Optimize the objective directly via gradient ascent on the policy parameters. High stability (performs true gradient ascent) but low sample efficiency.
  2. Value-Based Methods: Estimate the optimal Q-function \(Q^*(s, a)\) (e.g., Q-learning) without an explicit policy. High sample efficiency (off-policy) but poor convergence guarantees with neural networks.
  3. Actor-Critic: Combine both approaches. Train a critic (\(V\) or \(Q\)) to evaluate the policy, and an actor (\(\pi\)) to select actions.
  4. Model-Based RL: Learn the transition model \(p(s' \mid s, a)\) to plan or generate simulated data. Most sample-efficient, but suffers from compounding model errors.

Value-Based (Q-learning) Medium-High No (Non-linear case) Off-Policy
Actor-Critic Medium No (Non-linear case) Both

3.6 Key Takeaways

  • MDPs formalize sequential decision-making using states, actions, transitions, and rewards.
  • The core RL objective is to maximize the expected cumulative reward over trajectories.
  • Value functions and Q-functions represent expected future returns and decompose recursively.
  • Different RL algorithms trade off sample efficiency, convergence stability, and architectural assumptions.

Chapter 4: Policy Gradients

4.1 The Likelihood Ratio Trick

Policy gradient methods differentiate the expected return \(J(\theta) = \mathbb{E}_{\tau \sim p_\theta(\tau)} [r(\tau)] = \int p_\theta(\tau) r(\tau) d\tau\). The difficulty is that \(\theta\) changes the trajectory distribution itself. Differentiating gives:

\[ \nabla_\theta J(\theta) = \int \nabla_\theta p_\theta(\tau) r(\tau) d\tau \]

Using the identity \(\nabla_\theta p_\theta(\tau) = p_\theta(\tau) \nabla_\theta \log p_\theta(\tau)\) (the likelihood ratio trick), we write:

\[ \nabla_\theta J(\theta) = \int p_\theta(\tau) \nabla_\theta \log p_\theta(\tau) r(\tau) d\tau = \mathbb{E}_{\tau \sim p_\theta(\tau)} [\nabla_\theta \log p_\theta(\tau) r(\tau)] \]

The trajectory probability contains both the policy and the environment dynamics:

\[ \log p_\theta(\tau) = \log p(s_1) + \sum_{t=1}^H \left( \log \pi_\theta(a_t \mid s_t) + \log p(s_{t+1} \mid s_t, a_t) \right) \]

\[ \nabla_\theta \log p_\theta(\tau) = \sum_{t=1}^H \nabla_\theta \log \pi_\theta(a_t \mid s_t) \]

If the environment dynamics do not depend on \(\theta\), their gradient drops out. Thus, the policy gradient is model-free and does not require knowing the transition probabilities:

\[ \nabla_\theta J(\theta) = \mathbb{E}_{\tau \sim p_\theta(\tau)} \left[ \sum_{t=1}^H \nabla_\theta \log \pi_\theta(a_t \mid s_t) \left( \sum_{t'=1}^H r(s_{t'}, a_{t'}) \right) \right] \]

4.2 REINFORCE Algorithm

The REINFORCE algorithm estimates the expected policy gradient using empirical samples:

  1. Sample \(N\) trajectories \(\{\tau^{(i)}\}\) by running the policy \(\pi_\theta\) in the environment.
  2. Evaluate the gradient estimator:

\[ \nabla_\theta J(\theta) \approx \frac{1}{N} \sum_{i=1}^N \sum_{t=1}^H \nabla_\theta \log \pi_\theta(a_t^{(i)} \mid s_t^{(i)}) R(\tau^{(i)}) \]

  1. Update policy parameters: \(\theta \leftarrow \theta + \alpha \nabla_\theta J(\theta)\).

4.3 Variance Reduction

REINFORCE suffers from high variance because a single sample return \(R(\tau)\) determines the updates for all actions in the trajectory. Two techniques reduce this variance without introducing bias:

1. Causality (Reward-to-go)

Actions at time step \(t\) cannot affect rewards obtained at past time steps \(t' < t\). Therefore, we can replace the total return \(R(\tau)\) with the reward-to-go \(\hat{Q}_{t}\):

\[ \nabla_\theta J(\theta) = \mathbb{E} \left[ \sum_{t=1}^H \nabla_\theta \log \pi_\theta(a_t \mid s_t) \sum_{t'=t}^H r(s_{t'}, a_{t'}) \right] \]

2. Baseline Subtraction

We can subtract a state-dependent baseline \(b(s_t)\) from the return. The expected value of the baseline term is zero:

\[ \mathbb{E}_{a_t \sim \pi} [\nabla_\theta \log \pi_\theta(a_t \mid s_t) b(s_t)] = b(s_t) \int \pi_\theta(a_t \mid s_t) \frac{\nabla_\theta \pi_\theta(a_t \mid s_t)}{\pi_\theta(a_t \mid s_t)} da_t = b(s_t) \nabla_\theta (1) = 0 \]

Subtracting a baseline reduces variance without adding bias. A common simple choice is the average return of the sampled trajectories; in actor-critic methods, the baseline is usually a learned value function \(V_\phi(s_t)\).

The resulting policy gradient estimator is:

\[ \nabla_\theta J(\theta) \approx \frac{1}{N} \sum_{i=1}^N \sum_{t=1}^H \nabla_\theta \log \pi_\theta(a_t^{(i)} \mid s_t^{(i)}) \left( \sum_{t'=t}^H r(s_{t'}^{(i)}, a_{t'}^{(i)}) - b(s_t) \right) \]

4.4 Practical Implementation & Auto-Diff

In automatic differentiation frameworks (like PyTorch or TensorFlow), we implement policy gradients using a surrogate loss. For a discrete action distribution, the loss is defined as:

\[ \mathcal{L}(\theta) = - \frac{1}{N} \sum_{i=1}^N \sum_{t=1}^H \log \pi_\theta(a_t^{(i)} \mid s_t^{(i)}) A_t^{(i)} \]

where \(A_t^{(i)} = \left(\sum_{t'=t}^H r_{t'}^{(i)}\right) - b_t\) acts as the advantage weight. During backpropagation, \(A_t^{(i)}\) is treated as a fixed coefficient; the gradient flows through \(\log \pi_\theta\).

4.5 Key Takeaways

  • Policy gradients optimize policies directly by increasing the log-probability of actions weighted by their returns.
  • The likelihood ratio trick allows gradient estimation without knowing environment transition dynamics.
  • High variance is the primary drawback of policy gradients.
  • Variance can be reduced using causality (reward-to-go) and baseline subtraction, keeping the estimator unbiased.

Reward-to-go The sum of future rewards starting from the current time step

Chapter 5: Actor-Critic Algorithms

5.1 Actor-Critic Concept

The policy gradient formula is:

\[ \nabla_\theta J(\theta) = \sum_{t=1}^H \mathbb{E} \left[ \nabla_\theta \log \pi_\theta(a_t \mid s_t) A^\pi(s_t, a_t) \right] \]

In actor-critic methods, instead of estimating the advantage \(A^\pi(s, a)\) using high-variance Monte Carlo rollouts, we approximate it using learned value functions. - The Actor updates the policy parameters \(\theta\) in the direction of the policy gradient. - The Critic updates the parameters \(\phi\) of a value function estimator \(V_\phi(s)\) or \(Q_\phi(s, a)\) to evaluate the actor's actions.

5.2 Policy Evaluation (The Critic)

The critic's goal is to estimate \(V^\pi(s)\) under the current policy \(\pi\). This can be done via:

  1. Monte Carlo Evaluation: Regress \(V_\phi(s_t)\) directly to target returns:

\[ \mathcal{L}(\phi) = \frac{1}{2} \sum_{i} \left\| V_\phi(s_t^{(i)}) - G_t^{(i)} \right\|^2, \quad G_t^{(i)} = \sum_{t'=t}^H r(s_{t'}^{(i)}, a_{t'}^{(i)}) \]

  1. Temporal Difference (TD) Learning: Bootstrap the value function by regressing \(V_\phi(s_t)\) toward a one-step target:

\[ \mathcal{L}(\phi) = \frac{1}{2} \sum_{i} \left\| V_\phi(s_t^{(i)}) - \left( r(s_t^{(i)}, a_t^{(i)}) + \gamma V_\phi(s_{t+1}^{(i)}) \right) \right\|^2 \]

TD learning has much lower variance than Monte Carlo, though it introduces bias if \(V_\phi\) is inaccurate.

5.3 Advantage Actor-Critic (A2C/A3C)

Using the state value function \(V(s)\), the Q-value can be approximated as \(Q^\pi(s_t, a_t) \approx r(s_t, a_t) + \gamma V_\phi(s_{t+1})\). The advantage is then:

\[ A^\pi(s_t, a_t) \approx r(s_t, a_t) + \gamma V_\phi(s_{t+1}) - V_\phi(s_t) \]

This is the TD error. The basic Actor-Critic loop is:

  1. Collect transition \((s_t, a_t, r_t, s_{t+1})\) using \(\pi_\theta\).
  2. Compute target \(y_t = r_t + \gamma V_\phi(s_{t+1})\).
  3. Update critic parameters \(\phi\) to minimize \(\frac{1}{2}(V_\phi(s_t) - y_t)^2\).
  4. Evaluate advantage \(A_t = y_t - V_\phi(s_t)\).
  5. Update actor parameters \(\theta \leftarrow \theta + \alpha \nabla_\theta \log \pi_\theta(a_t \mid s_t) A_t\).

A3C (Asynchronous Advantage Actor-Critic) and A2C (Synchronous Advantage Actor-Critic) scale this using parallel workers to collect uncorrelated experience, replacing the need for an offline replay buffer.

5.4 Generalized Advantage Estimation (GAE)

To control the bias-variance tradeoff, we can define the advantage using \(n\)-step returns:

\[ A_t^{(n)} = \sum_{l=0}^{n-1} \gamma^l r_{t+l} + \gamma^n V_\phi(s_{t+n}) - V_\phi(s_t) \]

  • \(n=1\) yields the TD estimator (low variance, high bias).
  • \(n\to \infty\) yields the Monte Carlo estimator (high variance, zero bias).

Generalized Advantage Estimation (GAE) uses an exponential average of these \(n\)-step advantages, controlled by a hyperparameter \(\lambda \in [0, 1]\):

\[ A_t^{\text{GAE}(\gamma, \lambda)} = \sum_{l=0}^\infty (\gamma \lambda)^l \delta_{t+l}^V \]

where \(\delta_t^V = r_t + \gamma V_\phi(s_{t+1}) - V_\phi(s_t)\). - \(\lambda = 0\) reduces to TD(0). - \(\lambda = 1\) reduces to empirical Monte Carlo returns.

5.5 Key Takeaways

  • Actor-critic methods reduce policy gradient variance by replacing empirical returns with learned value estimators.
  • TD learning introduces bias but dramatically reduces variance compared to Monte Carlo returns.
  • State-value function critics evaluate advantages via the TD error.
  • GAE uses an exponential weighting parameter \(\lambda\) to balance the bias-variance tradeoff in advantage estimation.

Term Meaning

Chapter 6: Value-Based Methods and Q-Learning

6.1 Policy Iteration and Value Iteration

In tabular representations, we can solve for the optimal policy using dynamic programming:

  1. Policy Iteration: Alternates between complete policy evaluation and policy improvement:
    • Evaluate: Compute \(Q^\pi(s, a)\) for all states and actions.
    • Improve: Update policy \(\pi(s) \leftarrow \arg\max_a Q^\pi(s, a)\).
  2. Value Iteration: Directly updates values using the Bellman Optimality Equation:

\[ V_{k+1}(s) \leftarrow \max_{a} \left( r(s, a) + \gamma \sum_{s'} p(s' \mid s, a) V_k(s') \right) \]

6.2 Fitted Value Iteration and Q-Learning

For continuous or high-dimensional states, we approximate value functions using neural networks. Without a known transition model \(p(s' \mid s, a)\), we cannot evaluate every candidate action by explicitly rolling out the next state. Q-values avoid this by learning the value of state-action pairs directly from sampled transitions:

\[ Q(s, a) \leftarrow r(s, a) + \gamma \max_{a'} Q(s', a') \]

In Fitted Q-Iteration (FQI), we fit a Q-network \(Q_\phi(s, a)\) to bootstrapped targets \(y_i\) using transitions from a dataset:

\[ y_i = r_i + \gamma \max_{a'} Q_\phi(s'_i, a'), \quad \mathcal{L}(\phi) = \frac{1}{2} \sum_i \left\| Q_\phi(s_i, a_i) - y_i \right\|^2 \]

6.3 Deep Q-Networks (DQN)

Standard online Q-fitting fails with neural networks due to non-i.i.d. data and moving targets. DQN introduces two solutions:

  1. Replay Buffer: A dataset \(\mathcal{D}\) of historical transitions \((s, a, r, s')\). Batches are sampled uniformly to break temporal correlation and stabilize training.
  2. Target Network: A duplicate Q-network with frozen parameters \(\phi^-\). The target values are computed using \(\phi^-\), preventing feedback loops where updating \(Q\) also shifts the targets:

\[ y_i = r_i + \gamma \max_{a'} Q_{\phi^-}(s'_i, a') \]

The target parameters are slowly updated toward the online parameters: \(\phi^- \leftarrow \tau \phi + (1-\tau) \phi^-\) (or frozen and copied periodically).

6.4 Double DQN and Dueling DQN

Double DQN

Standard DQN overestimates Q-values because of the maximization operator: \(\mathbb{E}[\max(X_1, X_2)] \ge \max(\mathbb{E}[X_1], \mathbb{E}[X_2])\). Double DQN decouples the action selection from action evaluation: - Use the online network \(\phi\) to select the best action: \(a^* = \arg\max_a Q_\phi(s', a)\). - Use the target network \(\phi^-\) to evaluate the selected action:

\[ y_i = r_i + \gamma Q_{\phi^-}(s'_i, \arg\max_{a'} Q_\phi(s'_i, a')) \]

Dueling DQN

The dueling architecture splits the network output into a state value stream \(V(s)\) and an advantage stream \(A(s, a)\):

\[ Q(s, a) = V(s) + \left( A(s, a) - \frac{1}{|\mathcal{A}|} \sum_{a'} A(s, a') \right) \]

This separation helps the network learn state values without having to estimate values for every individual action.

6.5 Continuous Q-learning (DDPG)

In continuous action spaces, calculating \(\max_a Q(s, a)\) is difficult because we cannot enumerate actions. DDPG (Deep Deterministic Policy Gradient) addresses this by training a deterministic policy network \(\mu_\theta(s)\) that acts as an approximate maximizer, while the critic estimates \(Q_\phi(s,a)\):

\[ \theta \leftarrow \theta + \alpha \nabla_\theta J(\theta), \quad \nabla_\theta J(\theta) \approx \frac{1}{N} \sum_i \nabla_a Q_\phi(s_i, a) \mid_{a=\mu_\theta(s_i)} \nabla_\theta \mu_\theta(s_i) \]

6.6 Key Takeaways

  • Q-learning optimizes values off-policy, eliminating the need to model transition dynamics.
  • DQN uses a replay buffer and a target network to stabilize neural network function approximation.
  • Double DQN resolves overestimation bias by separating action selection from action evaluation.
  • Continuous action spaces require learning an approximate maximizer network (like in DDPG).

Dueling DQN A network architecture that separates state values from action advantages
Double Q-learning A formulation that mitigates positive maximization bias

Chapter 7: Advanced Policy Gradients

7.1 The Step Size Problem

In supervised learning, a bad gradient step usually only increases the training loss. In reinforcement learning, a bad policy update also changes the future data distribution: the policy may start collecting low-quality data, making recovery harder.

Trust-region methods constrain the update so the new policy remains close to the old policy.

7.2 Natural Policy Gradient

Standard gradient updates change parameters in Euclidean space. However, a small parameter change \(\|\delta\theta\|_2\) can cause a massive change in the output policy distribution. Natural Policy Gradient constrains the update step in the policy distribution space using the KL divergence:

\[ \max_{\delta\theta} \nabla_\theta J(\theta)^T \delta\theta \quad \text{subject to} \quad \mathbb{E}_{s \sim d^\pi} [\text{KL}(\pi_\theta(\cdot \mid s) \parallel \pi_{\theta + \delta\theta}(\cdot \mid s))] \le \epsilon \]

Using a second-order Taylor expansion on the constraint yields the Fisher Information Matrix (FIM) \(F\):

\[ \mathbb{E} [\text{KL}(\pi_\theta \parallel \pi_{\theta+\delta\theta})] \approx \frac{1}{2} \delta\theta^T F \delta\theta, \quad F = \mathbb{E}_{s \sim d^\pi, a \sim \pi} [\nabla_\theta \log \pi_\theta(a \mid s) \nabla_\theta \log \pi_\theta(a \mid s)^T] \]

The natural gradient update direction is:

\[ \theta_{k+1} = \theta_k + \alpha F^{-1} \nabla_\theta J(\theta) \]

7.3 Trust Region Policy Optimization (TRPO)

Computing and inverting the FIM \(F\) is impractical for deep networks. TRPO resolves this by optimizing the surrogate objective subject to the KL constraint using the conjugate gradient method:

\[ \max_\theta \mathbb{E} \left[ \frac{\pi_\theta(a \mid s)}{\pi_{\theta_{\text{old}}}(a \mid s)} A_{\theta_{\text{old}}}(s, a) \right] \quad \text{subject to} \quad \mathbb{E} [\text{KL}(\pi_{\theta_{\text{old}}} \parallel \pi_\theta)] \le \epsilon \]

The conjugate gradient method approximately solves \(F x = \nabla_\theta J(\theta)\) using matrix-vector products, avoiding explicit construction or inversion of the full matrix \(F\).

7.4 Proximal Policy Optimization (PPO)

TRPO remains mathematically complex and hard to parallelize. PPO replaces the hard KL constraint with a clipped surrogate objective that penalizes changes that move the policy ratio \(r_t(\theta) = \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\theta_{\text{old}}}(a_t \mid s_t)}\) too far from \(1.0\):

\[ L^{\text{CLIP}}(\theta) = \hat{\mathbb{E}}_t \left[ \min \left( r_t(\theta) A_t, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) A_t \right) \right] \]

  • If advantage \(A_t > 0\), the objective increases as \(r_t\) increases, but the clip limits updates when \(r_t > 1+\epsilon\).
  • If advantage \(A_t < 0\), the objective increases as \(r_t\) decreases, but the clip limits updates when \(r_t < 1-\epsilon\).

This simple objective can be optimized using standard SGD or Adam, achieving similar stability to TRPO.

7.5 Key Takeaways

  • Large policy updates can degrade the collected data quality, causing policy collapse.
  • Natural Policy Gradient constrains update steps in the policy distribution space rather than the parameter space.
  • TRPO uses a KL divergence constraint and solves it using conjugate gradients.
  • PPO simplifies this by clipping the policy ratio, providing a simple objective with similar stability.

Conjugate Gradient A numerical optimization method used to solve large linear systems

Chapter 8: Variational Inference and Control as Inference

8.1 Probabilistic Graphical Models for Decision Making

Control and planning can be formulated as probabilistic inference on a graphical model. We define binary "optimality" variables \(O_t\) whose likelihood increases with reward:

\[ p(O_t = 1 \mid s_t, a_t) \propto \exp(r(s_t, a_t)) \]

Assuming a uniform action prior \(p(a_t \mid s_t)\), the probability of a trajectory \(\tau\) conditioned on being optimal (\(O_{1:H} = 1\)) is:

\[ p(\tau \mid O_{1:H} = 1) \propto p(\tau) p(O_{1:H} = 1 \mid \tau) = p(s_1) \prod_{t=1}^H p(s_{t+1} \mid s_t, a_t) \exp(r(s_t, a_t)) \]

Solving for the optimal policy then corresponds to computing the posterior distribution \(p(a_t \mid s_t, O_{t:H}=1)\).

8.2 Variational Inference and ELBO

If we perform standard inference on \(p(\tau \mid O_{1:H}=1)\), the posterior may put probability mass on trajectories with unusually lucky transitions. This is the optimism problem: the agent behaves as if it could choose favorable stochastic outcomes.

Variational inference avoids this by searching over policy-driven trajectory distributions \(q(\tau) = p(s_1) \prod_t q(a_t \mid s_t) p(s_{t+1} \mid s_t, a_t)\), where the policy controls actions but not environment randomness. We maximize the Evidence Lower Bound (ELBO):

\[ \log p(O_{1:H}=1) \ge \mathbb{E}_{\tau \sim q(\tau)} [\log p(O_{1:H}=1, \tau) - \log q(\tau)] \]

Substituting the probabilities:

\[ \text{ELBO}(q) = \sum_{t=1}^H \mathbb{E}_{(s_t, a_t) \sim q} [r(s_t, a_t) + \mathcal{H}(q(\cdot \mid s_t))] \]

where \(\mathcal{H}\) is the entropy of the policy.

8.3 Maximum Entropy RL and SAC

Maximizing the ELBO motivates Maximum Entropy RL, which adds an entropy regularization term to the standard RL objective:

\[ J(\pi) = \sum_{t=1}^H \mathbb{E}_{(s_t, a_t) \sim \pi} [r(s_t, a_t) + \alpha \mathcal{H}(\pi(\cdot \mid s_t))] \]

The hyperparameter \(\alpha\) controls the tradeoff between reward seeking and entropy. Higher entropy keeps multiple actions plausible, which helps exploration and prevents premature collapse to a deterministic policy.

Soft Actor-Critic (SAC) implements this framework using: - Soft Q-critic: Updates Q-values using soft Bellman targets:

\[ y_t = r_t + \gamma \mathbb{E}_{s_{t+1}} [V(s_{t+1})], \quad V(s) = \mathbb{E}_{a \sim \pi} [Q(s, a) - \alpha \log \pi(a \mid s)] \]

  • Soft Actor: Minimizes the KL divergence between the policy and the soft Q-function:

\[ \mathcal{L}(\theta) = \mathbb{E}_{s \sim \mathcal{D}, a \sim \pi_\theta} [\alpha \log \pi_\theta(a \mid s) - Q_\phi(s, a)] \]

Using the reparameterization trick \(a = f_\theta(\epsilon; s)\), we can compute low-variance gradients for the actor.

8.4 Key Takeaways

  • Decision-making can be formulated as inference on graphical models with optimality variables.
  • Standard inference assumes optimistic transitions; variational inference restricts the search to valid environment dynamics.
  • Variational inference motivates the Maximum Entropy RL objective, which encourages exploration.
  • Soft Actor-Critic (SAC) optimizes this maximum entropy objective off-policy.

Term Meaning
Optimality Variable A binary variable representing whether a state-action pair is optimal
Optimism Problem The fallacy of acting as if favorable stochastic transitions can be chosen
ELBO Evidence Lower Bound, a variational lower bound on marginal log-likelihood
Maximum Entropy RL An RL objective that rewards both task success and policy randomness
SAC Soft Actor-Critic, a popular maximum entropy off-policy algorithm

Chapter 9: Reinforcement Learning from Human Feedback (RLHF) & LLM RL

9.1 LLM Finetuning and RL

Large Language Models (LLMs) are pre-trained on massive text datasets to predict the next token. This gives them broad linguistic and factual knowledge, but not necessarily assistant-like behavior. Instruction tuning via Supervised Fine-Tuning (SFT) helps, while preference optimization or RL can further refine outputs using human preferences or automated verifiers.

9.2 Preference Modeling (Bradley-Terry)

Human feedback is often collected as preferences between pairs of responses: given a prompt \(x\), a human identifies response \(y_w\) as better than \(y_l\). We model this preference using the Bradley-Terry model, assuming the probability of choosing \(y_w\) over \(y_l\) depends exponentially on a latent reward function \(r\):

\[ p(y_w \succ y_l \mid x) = \sigma(r(x, y_w) - r(x, y_l)) = \frac{1}{1 + \exp( - (r(x, y_w) - r(x, y_l)))} \]

A reward model \(r_\psi(x, y)\) is trained by minimizing the cross-entropy loss over a preference dataset:

\[ \mathcal{L}(\psi) = - \mathbb{E}_{(x, y_w, y_l) \sim \mathcal{D}} [\log \sigma(r_\psi(x, y_w) - r_\psi(x, y_l))] \]

9.3 RLHF with PPO

Once the reward model \(r_\psi\) is trained, the LLM policy \(\pi_\theta(y \mid x)\) is optimized using RL. To prevent the policy from exploiting the reward model (reward hacking) or drifting too far from valid text, we add a KL divergence penalty relative to the reference SFT model \(\pi_{\text{SFT}}\):

\[ R(x, y) = r_\psi(x, y) - \beta \log \frac{\pi_\theta(y \mid x)}{\pi_{\text{SFT}}(y \mid x)} \]

The objective is optimized using PPO: - Actor: The LLM policy generating tokens. - Critic: A value network estimating the expected reward-to-go for intermediate token states. - Reference Model: A frozen copy of the SFT model used to calculate the KL penalty.

GRPO (Group Relative Policy Optimization) is an alternative that eliminates the critic network. It samples a group of completions for each prompt and uses their relative rewards as advantages, reducing GPU memory footprint during training.

9.4 Direct Preference Optimization (DPO)

PPO-style RLHF is computationally expensive because training may involve an actor, critic, reference model, and reward model. DPO avoids explicitly training a reward model and running an RL loop. Under the Bradley-Terry preference model with a KL regularizer, the preference objective can be rewritten as a direct supervised-style loss on preference pairs:

\[ \mathcal{L}_{\text{DPO}}(\theta) = - \mathbb{E}_{(x, y_w, y_l) \sim \mathcal{D}} \left[ \log \sigma \left( \beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\text{SFT}}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\text{SFT}}(y_l \mid x)} \right) \right] \]

This formulation uses the same basic interface as SFT: prompts, chosen responses, rejected responses, and log-probabilities under the current and reference policies.

9.5 Key Takeaways

  • Preference optimization helps align LLMs with human preferences beyond pure imitation learning.
  • The Bradley-Terry model maps pairwise preferences to scalar rewards.
  • Standard RLHF uses PPO with a reference KL penalty to prevent reward hacking.
  • DPO optimizes LLMs directly on preferences using an analytical solution, avoiding the need for reward models and critic networks.

Term Meaning
SFT Supervised Fine-Tuning, training LLMs to imitate demonstration text
Bradley-Terry Model A mathematical model representing preference probabilities between pairs
Reward Hacking Exploiting loopholes in reward models to get high scores without solving the task
GRPO A memory-efficient policy gradient method that replaces the critic with group statistics
DPO Direct Preference Optimization, a method for training LLMs directly on preference data

Chapter 10: Model-Based Reinforcement Learning

10.1 Learning Dynamics Models

Model-based RL learns a transition model of the environment, either deterministic \(s_{t+1} = f_\theta(s_t, a_t)\) or probabilistic \(p_\theta(s_{t+1} \mid s_t, a_t)\). The agent can then use the model for planning or simulated training.

The main advantage is sample efficiency: fitting a dynamics model is a supervised learning problem, so it can reuse each real transition many times. The main risk is model bias. Small one-step prediction errors can compound over long rollouts and push simulated states away from the real data distribution.

10.2 Model Predictive Control (MPC) & Planning

Instead of training a policy, we can use the dynamics model to plan actions:

  1. Open-Loop Planning: Find a sequence of actions \((a_1, \dots, a_H)\) that maximizes expected reward.
    • Random Shooting: Sample random action sequences, evaluate them using the model, and execute the best sequence.
    • Cross-Entropy Method (CEM): Sample action sequences from a Gaussian distribution, evaluate them, fit a new Gaussian to the top-performing sequences, and repeat.
  2. Model Predictive Control (MPC): Converts open-loop planning into a closed-loop controller. The agent plans a sequence \((a_t, \dots, a_{t+H})\), executes only the first action \(a_t\), receives the next state \(s_{t+1}\) from the real environment, replans from \(s_{t+1}\), and repeats. Re-planning at each step corrects for model inaccuracies.

10.3 Policy Optimization with Models

To avoid the cost of planning at runtime, we can use the model to train a policy \(\pi_\phi(a \mid s)\):

  1. Dyna-Style RL: The agent collects real transitions, trains the dynamics model, generates simulated transitions from the model, and updates a model-free RL algorithm (like Q-learning) using the simulated data.
  2. MBPO (Model-Based Policy Optimization): Limits compounding error by running only short model-based rollouts (e.g., 1-5 steps) starting from states visited in the real environment.
  3. Latent Dynamics Models: For visual tasks, planning directly on pixels is difficult. Algorithms like Dreamer learn a latent representation \(z_t\) and train transition models in this latent space, optimizing the policy entirely within the learned representation.

10.4 Key Takeaways

  • Model-based RL improves sample efficiency by learning environment dynamics via supervised learning.
  • Compounding prediction errors limit the horizon of model-based rollouts.
  • MPC mitigates model inaccuracy by planning action sequences but executing only the first step.
  • Dyna-style methods and latent dynamics models allow policies to learn within simulated environments.

10.5 Vocabulary

Term Meaning
Dynamics Model A function approximating the environment's transition probabilities
Compounding Error The accumulation of prediction errors over time steps
MPC Model Predictive Control, a framework that plans future actions but executes only the immediate next step
CEM Cross-Entropy Method, an optimization technique that refines sampling distributions iteratively
Latent Dynamics Models that predict transitions in a low-dimensional feature space rather than raw observations

Chapter 11: Offline Reinforcement Learning

11.1 The Offline RL Challenge

In standard RL, the agent collects new data using its updated policy. In Offline RL, the agent learns from a static dataset \(\mathcal{D}\) without environment interaction.

The core challenge is distributional shift. If the learned policy chooses an action \(a'\) rarely represented in the dataset, the Q-function must extrapolate. Q-learning then propagates values through \(\max_{a'} Q(s', a')\), so overestimated out-of-distribution (OOD) actions can be repeatedly selected and amplified.

11.2 Policy Constraint Methods

Policy constraint methods prevent the policy \(\pi_\theta\) from choosing out-of-distribution actions. They restrict updates to remain close to the behavior policy \(\pi_\beta\) that generated the dataset:

  1. Explicit Constraints: Directly penalize divergence during policy updates:

\[ \max_\theta \mathbb{E}_{s \sim \mathcal{D}, a \sim \pi_\theta} [Q(s, a)] - \alpha \mathcal{D}_{\text{KL}}(\pi_\theta(\cdot \mid s) \parallel \pi_\beta(\cdot \mid s)) \]

This requires estimating the behavior policy \(\pi_\beta\) from the dataset.

  1. Implicit Constraints: Update policies without estimating \(\pi_\beta\) by using weighted likelihood maximization. For example, AWAC (Advantage Weighted Actor-Critic) updates the policy using:

\[ \theta \leftarrow \arg\max_\theta \mathbb{E}_{(s, a) \sim \mathcal{D}} \left[ \log \pi_\theta(a \mid s) \exp \left( \frac{1}{\beta} A(s, a) \right) \right] \]

Since actions are drawn directly from the dataset, the policy remains within the support of the behavior policy.

11.3 Value Regularization & Implicit Q-Learning

Instead of constraining the policy, value regularization methods modify the Q-function training:

  1. CQL (Conservative Q-Learning): Minimizes Q-values for actions chosen by the policy while maximizing Q-values for actions represented in the dataset:

\[ \min_Q \mathbb{E}_{s \sim \mathcal{D}} \left[ \log \sum_a \exp(Q(s, a)) - \mathbb{E}_{a \sim \pi_\beta} [Q(s, a)] \right] + \frac{1}{2} \mathbb{E}_{(s, a, r, s') \sim \mathcal{D}} \left[ (Q(s, a) - \mathcal{T}Q(s, a))^2 \right] \]

This encourages conservative Q-values, especially for actions not well supported by the dataset. It reduces overestimation, though the strength of the guarantee depends on assumptions and implementation details.

  1. IQL (Implicit Q-Learning): Bypasses out-of-distribution actions entirely by updating the value function using expectile regression. IQL learns \(V(s)\) to approximate the upper value statistics in the dataset:

\[ \mathcal{L}(V) = \mathbb{E}_{(s, a) \sim \mathcal{D}} [L_2^\tau (Q_{\psi^-}(s, a) - V_\psi(s))] \]

where \(L_2^\tau(u) = |\tau - \mathbb{I}(u < 0)| u^2\) is the expectile loss. Expectiles are asymmetric squared-loss statistics, not the same as quantiles. Setting \(\tau \in [0.7, 0.9]\) makes \(V(s)\) track high-value in-dataset actions without explicitly maximizing over OOD actions.

11.4 Key Takeaways

  • Offline RL learns from static data without environment interaction.
  • Distributional shift causes Q-learning to overestimate out-of-distribution actions.
  • Policy constraint methods limit the policy to actions represented in the dataset.
  • CQL regularizes Q-values downward for OOD actions, while IQL avoids OOD queries entirely using expectile regression.

Expectile Regression An asymmetric squared-loss regression used to estimate expectiles of a distribution

Chapter 12: Exploration and Advanced Exploration

12.1 Exploration vs. Exploitation

The exploration-exploitation tradeoff describes the choice between: - Exploitation: Choosing actions known to yield high rewards. - Exploration: Choosing unfamiliar actions to discover better strategies.

In Multi-Armed Bandits (one-step MDPs), we evaluate exploration using regret, the difference between the optimal expected reward and the collected reward. Two classic exploration strategies are: 1. Upper Confidence Bound (UCB): Follows the principle of optimism under uncertainty. It chooses actions using an uncertainty bonus:

\[ a_t = \arg\max_a \left( \hat{\mu}_a(t) + c \sqrt{\frac{\log t}{N_a(t)}} \right) \]

  1. Thompson Sampling: Maintains a posterior distribution over rewards for each action. The agent samples rewards from these posteriors and executes the action with the highest sample.

12.2 Count-Based Exploration & Pseudo-Counts

In tabular MDPs, we can apply UCB-like optimism by adding an exploration bonus to rewards: \(r^i(s, a) = r(s, a) + \frac{\beta}{\sqrt{N(s)}}\). For continuous state spaces, we rarely visit the same state twice, making direct counting impossible. Pseudo-counts resolve this by estimating state densities using generative models:

\[ N(s) \approx \frac{p(s)(1 - p'(s))}{p'(s) - p(s)} \]

where \(p(s)\) is the density model before observing \(s\), and \(p'(s)\) is the model after updating it with \(s\). If observing \(s\) greatly increases its modeled density, the state is treated as rare and receives a larger exploration bonus.

12.3 Novelty Search (Random Network Distillation)

Density estimation is difficult in high-dimensional spaces. RND (Random Network Distillation) replaces density estimation with prediction error: - A target network \(f(s)\) is randomly initialized and frozen. - A predictor network \(\hat{f}_\theta(s)\) is trained to predict the outputs of the target network. - The exploration bonus is defined as the prediction error:

\[ r^i(s) = \left\| \hat{f}_\theta(s) - f(s) \right\|^2 \]

In familiar states, the predictor network generalizes well, yielding low error. In novel states, the error is high, directing the agent toward unexplored areas.

12.4 Skill Learning and Empowerment

In the absence of external rewards, agents can learn behaviors by maximizing mutual information between states and latent skill variables \(z \sim p(z)\):

\[ I(S; Z) = \mathcal{H}(Z) - \mathcal{H}(Z \mid S) = \mathcal{H}(S) - \mathcal{H}(S \mid Z) \]

Maximizing this objective motivates: - Empowerment: Learning policies that give the agent control over its future states. - DIAYN (Diversity is All You Need): Trains a policy \(\pi(a \mid s, z)\) and a discriminator \(D(z \mid s)\). The agent is rewarded when the discriminator can identify the skill \(z\) from the visited states, encouraging skills to visit distinct regions of the state space.

12.5 Key Takeaways

  • Bandit theory provides classic exploration tools like UCB and Thompson Sampling.
  • Pseudo-counts extend count-based exploration to continuous state spaces using density models.
  • RND uses target network prediction errors as simple, effective exploration bonuses.
  • Unsupervised skill learning uses mutual information maximization to discover diverse behaviors.

Term Meaning

Chapter 13: Reinforcement Learning Theory

13.1 Sample Complexity

RL theory asks how many samples are needed to learn a policy whose expected return is within \(\epsilon\) of optimal. These are usually called PAC-style sample complexity bounds.

Before sample bounds, we need the basic stability property of dynamic programming. In tabular MDPs, the Bellman Optimality Operator \(\mathcal{T}^*\) is:

\[ (\mathcal{T}^* V)(s) = \max_a \left( r(s, a) + \gamma \sum_{s'} p(s' \mid s, a) V(s') \right) \]

Under the \(\mathcal{L}_\infty\) norm, \(\mathcal{T}^*\) is a \(\gamma\)-contraction mapping:

\[ \left\| \mathcal{T}^* V_1 - \mathcal{T}^* V_2 \right\|_\infty \le \gamma \left\| V_1 - V_2 \right\|_\infty \]

By the Banach Fixed-Point Theorem, value iteration converges to a unique optimal value function \(V^*\), and the error after \(k\) iterations is bounded by:

\[ \left\| V_k - V^* \right\|_\infty \le \gamma^k \left\| V_0 - V^* \right\|_\infty \]

Sample complexity results combine this contraction property with concentration inequalities that bound how far empirical transition estimates are from the true dynamics.

13.2 Error Bounds & Simulation Lemma

When learning transition models, we bound how dynamics errors propagate to the value function. The Simulation Lemma states that if the dynamics transition error is bounded by \(\epsilon_p\):

\[ \max_{s, a} \left\| p(\cdot \mid s, a) - \hat{p}(\cdot \mid s, a) \right\|_1 \le \epsilon_p \]

then the value function error of any policy \(\pi\) evaluated in the learned dynamics model \(\hat{p}\) is bounded by:

\[ \left\| V^\pi - \hat{V}^\pi \right\|_\infty \le \frac{\gamma \text{R}_{\max}}{(1-\gamma)^2} \epsilon_p \]

This quadratic dependence on the effective horizon \(\frac{1}{1-\gamma}\) explains why model-based rollouts require high-precision dynamics models.

13.3 Key Takeaways

  • Tabular Bellman operators are contraction mappings under the infinity norm, guaranteeing value iteration convergence.
  • Concentration inequalities bound the discrepancy between empirical transitions and true dynamics.
  • The Simulation Lemma shows value function errors scale quadratically with the effective horizon.

13.4 Vocabulary

Term Meaning
Contraction Mapping An operator that reduces the distance between any two points in a metric space
PAC Probably Approximately Correct, a theoretical framework for learning guarantees
Simulation Lemma A theorem bounding value function errors based on transition dynamics errors
Union Bound A theorem stating the probability of at least one of many events occurring is less than the sum of their individual probabilities

Chapter 14: Multi-Task and Meta-Reinforcement Learning

14.1 Multi-Task RL

Multi-task RL learns a single policy \(\pi(a \mid s, z)\) for many tasks, where \(z\) is a task context such as a language command or goal. Shared representations can improve sample efficiency, but optimization is harder when gradients from one task hurt performance on another (gradient interference).

Hindsight Experience Replay (HER)

For goal-conditioned RL, rewards are often sparse. HER addresses this by relabeling goals. For any transition sequence where the agent failed to reach the target goal \(g\), HER relabels the transition with a goal \(g'\) that the agent did actually reach, converting failures into successful training examples.

14.2 Meta-Reinforcement Learning

Meta-RL aims to "learn to learn." Instead of only solving the training tasks, it trains across a task distribution so the agent can adapt to a new task using only a few trial transitions:

  1. Recurrent Meta-RL (\(RL^2\)): The policy is represented as a recurrent network (e.g., LSTM). The network's hidden state is not reset between episodes of the same task, allowing the RNN to implicitly run an adaptation algorithm in its activations.
  2. Gradient-Based Meta-RL (MAML): Optimizes policy parameters \(\theta\) such that taking a single gradient step on a new task yields high performance:

\[ \max_\theta \sum_{i} J_i(\theta - \alpha \nabla_\theta J_i(\theta)) \]

14.3 Key Takeaways

  • Multi-task RL shares representations across tasks but can suffer from gradient interference.
  • Hindsight Experience Replay improves goal-conditioned learning by relabeling failed goals.
  • Meta-RL trains policies to adapt to new tasks using a few trial transitions.
  • Meta-RL can be implemented using recurrent networks (\(RL^2\)) or gradient-based meta-optimization (MAML).

14.4 Vocabulary

Term Meaning
Relabeling Modifying transition goals in a replay buffer to densify rewards
HER Hindsight Experience Replay, a goal relabeling technique
Meta-RL Algorithms designed to adapt to new tasks using minimal samples
MAML Model-Agnostic Meta-Learning, a gradient-based meta-learning framework

Chapter 15: Challenges and Open Problems

15.1 Core Challenges in Deep RL

Despite successes, deep reinforcement learning faces major challenges:

  1. Sample Efficiency: Model-free methods require millions of interactions, limiting their use in physical systems like robotics.
  2. Generalization: Policies are often fragile and fail when transition dynamics or observations change slightly (overfitting to seeds/environments).
  3. Reward Design: Defining dense reward functions that align with human intent is difficult, often leading to reward hacking.

15.2 Future Horizons

The frontier of RL research focuses on: - Offline Pre-training: Bootstrapping RL using large offline datasets (similar to foundation models in computer vision and language). - Continual Autonomous Learning: Designing agents that can adapt and improve indefinitely in open-world environments without human resets. - Moravec's Paradox: Addressing the difficulty of replicating simple human motor skills (like grasping objects) compared to abstract logical tasks (like playing chess).

15.3 Key Takeaways

  • Core challenges in RL include sample efficiency, generalization, and reward alignment.
  • Future directions emphasize building foundation models for decision-making.
  • Real-world deployment requires shift-robust, reset-free, and continually adapting systems.

Term Meaning

Continual Learning The ability of an agent to acquire new skills without forgetting past knowledge

“信息安全的核心不是完美的技术，而是有效的管理与人性化的考虑。” —— Bruce Schneier

什么是敏感信息？

在项目开源的过程中，不可避免地会碰到敏感信息，例如：

  • 云数据库的账号密码信息
    MySQL等数据库的用户名和密码。
  • 微信登录涉及的 AppID、AppSecret
    这些信息用于第三方服务的 OAuth 认证，如果泄露可能导致账号被恶意使用。
  • API 密钥
    用于调用第三方服务的 API_KEY，如支付网关、地图服务、邮件发送等。
  • SSH 私钥
    服务器管理中的 SSH 私钥文件，如果泄露会让攻击者获得服务器的完全访问权限。
  • JWT Secret
    这些密钥用于生成和验证 JWT，保护用户身份信息。
  • 支付信息
    例如：银行卡号、支付网关的密钥（如支付宝的签名密钥）。
  • 个人身份信息（PII）
    例如：身份证号码、护照信息、电话号码、住址、电子邮件地址等。
  • 密码文件
    例如：包含用户登录密码或哈希密码的配置文件、.env 文件中明文存储的敏感数据。

这些敏感信息如果在开源项目中暴露，可能会引发数据泄露、财务损失、甚至法律责任等严重后果，因此在项目中需要妥善处理和保护。

当编译器发现某个包的名字为 main 时，它一定也会发现名为 main()的函数，否则不会创建可执行文件。 main()函数是程序的入口，所以，如果没有这个函数，程序就没有办法开始执行。

程序编译时，会使用声明 main 包的代码所在的目录的目录名作为二进制可执行文件的文件名。

序列化和反序列化

Java 序列化是一种将对象转换为字节流的过程，以便可以将对象保存到磁盘上，将其传输到网络上，或者将其存储在内存中，以后再进行反序列化，将字节流重新转换为对象。

序列化在 Java 中是通过 java.io.Serializable 接口来实现的，该接口没有任何方法，只是一个标记接口，用于标识类可以被序列化。

当你序列化对象时，你把它包装成一个特殊文件，可以保存、传输或存储。反序列化则是打开这个文件，读取序列化的数据，然后将其还原为对象，以便在程序中使用。

2024-04-02

前端基础

1.前端开发介绍

那在讲解web前端开发之前，我们先需要对web前端开发有一个整体的认知。主要明确一下三个问题：

1). 网页有哪些部分组成 ?

文字、图片、音频、视频、超链接、表格等等。

2). 我们看到的网页，背后的本质是什么 ?

程序员写的前端代码 (备注：在前后端分离的开发模式中，)

3). 前端的代码是如何转换成用户眼中的网页的 ?

通过浏览器转化（解析和渲染）成用户看到的网页

浏览器中对代码进行解析和渲染的部分，称为 浏览器内核

而市面上的浏览器非常多，比如：IE、火狐Firefox、苹果safari、欧朋、谷歌Chrome、QQ浏览器、360浏览器等等。 而且我们电脑上安装的浏览器可能都不止一个，有很多。

但是呢，需要大家注意的是，不同的浏览器，内核不同，对于相同的前端代码解析的效果也会存在差异。 那这就会造成一个问题，同一段前端程序，不同浏览器展示出来的效果是不一样的，这个用户体验就很差了。而我们想达到的效果则是，即使用户使用的是不同的浏览器，解析同一段前端代码，最终展示出来的效果都是相同的。

要想达成这样一个目标，我们就需要定义一个统一的标准，然后让各大浏览器厂商都参照这个标准来实现即可。 而这套标准呢，其实早都已经定义好了，那就是我们接下来，要介绍的web标准。

Web标准也称为网页标准，由一系列的标准组成，大部分由W3C（ World Wide Web Consortium，万维网联盟）负责制定。由三个组成部分：

  • HTML: HyperText Markup Language，超文本标记语言。

    • 超文本：超越了文本的限制，比普通文本更强大。除了文字信息，还可以定义图片、音频、视频等内容。

    • 标记语言：由标签构成的语言

      • HTML标签都是预定义好的。例如：使用

        标签展示标题，使用展示超链接，使用展示图片，

      • HTML代码直接在浏览器中运行，HTML标签由浏览器解析。
  • CSS：Cascading Style Sheet，层叠样式表，负责网页的表现（页面元素的外观、位置等页面样式，如：颜色、大小等）。
  • JavaScript：负责网页的行为（交互效果）。

当然了，随着技术的发展，我们为了更加快速的开发，现在也出现了很多前端开发的高级技术。例如：vue、elementui、Axios等等。
